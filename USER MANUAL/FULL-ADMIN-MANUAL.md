# Zaks Foods Sales Portal: Admin Manual

## 1. System Overview
The Zaks Sales Portal is a standalone web application built with React/Vercel that communicates with a Supabase PostgreSQL database. It integrates with Oracle NetSuite via custom SuiteScript Suitelets that process CSV files generated by the portal.

## 2. Managing Users

### Creating a New User
1. Log in to the **Supabase Dashboard**.
2. Navigate to **Authentication > Users**.
3. Click **Add User** -> **Create New User**.
4. Enter the user's Email and a temporary Password.
5. Uncheck "Auto Confirm User" if you want them to receive an email confirmation, or check it if you want to grant immediate access.
6. Click **Create User**.

### Assigning Roles (Admin vs Rep)
By default, new users have standard sales rep privileges. To grant Admin privileges (to see all customers and system logs):
1. In Supabase, go to the **Table Editor**.
2. Open the `user_roles` table.
3. Insert a new row linking the new `user_id` to the `role_id` for "ADMIN".

### Sending Login Information
Since the portal is private, users must be provided with the portal URL: `https://zaks-lion-sales-portal.vercel.app/`
Provide the user with the temporary password you created. They can use the "Forgot Password" link on the portal login page to reset it if needed.

## 3. NetSuite Integration & Scripts

The portal relies on two core Suitelets to import transactions. If you ever need to update the logic for these, you must update the scripts in NetSuite.

### Updating Scripts
1. Go to **Customization > Scripting > Scripts**.
2. Locate the script you want to update (e.g., `Zaks Portal Create Invoice from CSV`).
3. Edit the script record.
4. On the **Script File** dropdown, click the pencil icon to edit the file, and paste the updated JavaScript code over the existing code.
5. Click **Save** on the file, then **Save** on the Script record. *(Saving the script record purges NetSuite's cache).*

### Hardcodes and Locks
***** IMPORTANT: DSD INVOICE WAREHOUSE LOCK *******
Currently, when a rep submits a Direct Store Delivery (DSD) Invoice, the warehouse is strictly hardcoded in the Portal to **Zaks - Edmonton Warehouse**. 
- The portal will prevent submission if the inventory at this specific warehouse is zero.
- The `CreateInvoiceFromCSV_SL.js` Suitelet dynamically maps "Zaks - Edmonton Warehouse" to internal ID `2` in NetSuite.
- **If you ever need to change the DSD warehouse, you must update the React portal code (`OrderBuilder.tsx`) to change the target warehouse name, and ensure the Suitelet `locationMap` includes it.**

## 4. Troubleshooting

### Portal Errors
- **"Cannot submit DSD Invoice: Insufficient inventory..."**: This occurs if the rep tries to invoice more product than is currently physically available in the **Zaks - Edmonton Warehouse**. The rep must reduce the quantity, or you must adjust inventory in NetSuite.
- **Missing Activity Logs**: If an activity doesn't log to the timeline, ensure the `activity_type` string in the portal strictly matches one of the allowed CHECK constraint keywords in the Supabase `activities` table (e.g., `DRAFT_ORDER`, `VISIT`, `NOTE`).

### NetSuite Import Errors
When uploading a CSV to a Suitelet, you may encounter these errors:
- **"Please configure the inventory detail for this line"**: The location you are trying to invoice from has "Use Bins" enforced. Direct invoices cannot be created via CSV for bin-enforced locations. Use the Edmonton warehouse bypass, or manually create the invoice in NetSuite.
- **"Amount Error" / Pricing Missing**: The customer's assigned Price Level does not have a defined price for one of the SKUs on the order. You must fix the item pricing on the Item Record in NetSuite before importing.
- **Missing SKUs**: If the portal allows a SKU that NetSuite doesn't recognize, the Suitelet will skip the item and put a huge `[WARNING: SKIPPED MISSING SKUs: ...]` note in the Memo field of the transaction. Verify the SKU names match exactly between Supabase and NetSuite.
