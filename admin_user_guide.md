# Administrative User Guide: CSV Imports & Costing Logic

This guide provides a comprehensive breakdown of the CSV import processes for Customer Creation and Draft Sales Orders into NetSuite. It details required inputs, formatting logic, and exactly how the system calculates item costing when data is not explicitly provided.

---

## 1. Customer Creation CSV Import
**SuiteScript:** `CreateCustomerFromCSV_SL.js`

This script parses a CSV file and automatically generates a Customer record, an Address subrecord, and up to two Contact records (Primary and Accounts Payable) in NetSuite.

### Required Fields
The following fields **must** be provided for the script to successfully create a customer:
- `Customer Name`: The core name of the customer.
  - *Formatting Note:* The script automatically applies **Title Case** to this field (e.g., "zaks foods" becomes "Zaks Foods").

### Optional Fields
All other fields are technically optional, but highly recommended for a complete record:
- `Legal Name`: Appended to the NetSuite "Comments" field. Also formatted as Title Case.
- `Primary Email` / `Primary Phone`
- `AP Email` / `AP Phone`
- `Primary Contact First` / `Primary Contact Last`
- `AP First Name` / `AP Last Name`
- `Banner` / `Channel`
- `Shipping Address`, `City`, `Province`, `Postal Code`
  - *Formatting Note (Province):* Automatically normalized to 2-letter codes (e.g., "Alberta" -> "AB").
  - *Formatting Note (Postal Code):* Automatically formats valid 6-character Canadian postal codes to `A1A 1A1` format.

### How Pricing is Set for Customers
Costing rules for a specific customer are dictated entirely by the **`Price Level`** field provided in the CSV. 
The script maps the string value in your CSV to the NetSuite Internal ID. The supported mappings are:

| CSV Value (Case-Insensitive) | NetSuite Internal ID |
|------------------------------|----------------------|
| `Retail` | 1 |
| `Store` | 2 |
| `Distributor` | 3 |
| `MasterDist` | 4 |
| `Online Price` | 5 |
| `CTire` | 8 |
| `PAFineFoods` | 9 |
| `OtherDist` | 10 |
| `FITC` | 11 |
| `Wholesale` | 14 |
| `Canco Price` | 18 |

If this field is omitted or misspelled in the CSV, the Customer record is created **without** a default Price Level.

## 2. Draft Sales Order CSV Import
**SuiteScript:** `CreateSalesOrderFromCSV_SL.js`

This script takes the Draft Order CSV generated by the Sales Portal and translates it into a NetSuite Sales Order. 

### Required Fields
- `Customer ID`: The Internal ID of the customer in NetSuite.
- `SKU`: The Item ID/Name in NetSuite.
- `Quantity`: The number of units ordered.

### How Order Costing is Calculated
The Draft Order CSV deliberately **omits** base pricing for standard items. Here is exactly how the system figures out the price:

#### Scenario A: Standard Pricing (No Override)
If the sales rep does **not** explicitly override the price in the portal:
1. The CSV exports with a **blank** `Rate` field.
2. When the script adds the item to the Sales Order, it only sets the `Item` and the `Quantity`.
3. NetSuite's dynamic engine takes over. It looks at the Customer's designated **Price Level** (set during customer creation). 
4. NetSuite automatically pulls the base price for that specific item at that specific Price Level and populates the line amount.
   - *Error Handling:* If the item does not have a price configured for the customer's specific Price Level, NetSuite will throw an error (`"Failed to add Item... NetSuite could not determine a price"`). 

#### Scenario B: Custom Pricing (Override Provided)
If the sales rep **does** provide an override price in the portal:
1. The CSV exports with that value in the `Rate` column.
2. The script recognizes that a custom rate is provided.
3. **CRITICAL STEP:** The script explicitly forces the Line Item's **Price Level** field to `Custom` (Internal ID: `-1`). 
4. The script then applies the custom `Rate` to the line. 
   - *Why this happens:* If the script did not set the Price Level to Custom, NetSuite would ignore the provided rate and overwrite it with the customer's default base price.
